    Two planes, one signed intent
    
    
    The Control Plane plans from the user's request only, signs a Semantic Provenance Token (SPT) for each delegated step, and checks everything that comes back. The Data Plane runs tools in a sandbox and is treated as hostile. Tool requests cross the boundary only with a token, and results return only through verification.

    What this prototype does not prove
    
    
      
      
    • The agent is a local Ollama model (DPVG_OLLAMA_MODEL). If Ollama is not running or the model is not pulled, runs fail with an error; there is no fallback model.
      • 
      
    • The embedder is the bundled all-MiniLM-L6-v2 (ONNX). There is no fallback embedder. Re-calibrate τ if you switch to DPVG_EMBEDDER=st.
      • 
      
    • Stage B alone misses attacks that sound like the user's task. Scope bounds and lineage checks are the second line of defense.
      • 
      
    • Benign emails and pages that contain polite requests can be flagged, which costs task completion.
